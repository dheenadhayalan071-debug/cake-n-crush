# Cake N Crush — playful premium patisserie

A production-ready, mobile-first marketing and catalogue site for **Cake N Crush**, a
patisserie and cake shop in Park Town, Madurai, Tamil Nadu.

Art direction: **Playful Premium Patisserie** — expressive Fraunces headlines on the
`SOFT`/`WONK` axes, purposeful pastel colour fields (butter, cherry, pistachio,
strawberry, lavender, sky), chunky printed-feeling cards, and exact variant-level pricing.
Colourful and art-directed, deliberately not a cartoon and not beige minimalism.

Ordering is WhatsApp-first. No checkout, no accounts, no database, no backend.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # production build → dist/
npm run verify   # content audit + tests + build
```

## Stack

| Concern    | Choice                                   | Why |
| ---------- | ---------------------------------------- | --- |
| Framework  | React 19 + Vite 8                        | Fast builds, tiny output, no framework overhead for 6 static routes. |
| Styling    | Tailwind CSS 4 (`@tailwindcss/vite`)     | Design tokens live in CSS; no config sprawl. |
| Motion     | Framer Motion, gated                     | Reveals and transitions only run when `IntersectionObserver` exists **and** reduced motion is off; otherwise content renders plain and visible. See `docs/MOTION.md`. |
| Icons      | Lucide React + 2 hand-written brand SVGs | No icon-pack bulk for Instagram/Facebook. |
| Routing    | React Router 7                           | Shareable catalogue URLs (`/menu?category=eggless`, `/menu?product=red-velvet`). |
| Fonts      | Self-hosted Fraunces (variable) + Instrument Sans | One 121 kB file carries every display weight plus the `SOFT`/`WONK` axes that give the headlines their character. No third-party requests, no CLS. |
| Images     | Sharp build pipeline → responsive WebP   | 3 widths per image + inline LQIP blur; committed output. |
| Tests      | Vitest + Testing Library + jsdom         | **158 tests**: prices, WhatsApp links, validation, every route, SEO tags, a11y, dialogs, imagery, and a rendered-visibility guard against the blank-section outage. |

No analytics, no tracking scripts, no external APIs at runtime.

## Editing the site (owner / non-developer guide)

Everything the business might want to change lives in `src/data/`.

**Contact details, WhatsApp, hours, delivery-app links** → `src/data/business.js`

```js
export const BUSINESS = {
  ...
  openingHours: null,   // e.g. '10:00 – 21:00, daily' once confirmed
  swiggyUrl: null,      // paste the official listing URL
  zomatoUrl: null,
  instagramUrl: null,
};
```

When a URL is `null`, the interface shows an honest "pending" note instead of a dead link.

**Prices and products** → `src/data/products.js`. A price always belongs to a *variant*
(weight + dietary type). Never add a second hard-coded price field.

```js
{
  id: 'black-forest',
  name: 'Black Forest',
  categories: ['celebration', 'eggless', 'onekg'],
  variants: [
    { id: 'regular-500g', dietaryType: 'Regular', weight: '500g', weightGrams: 500, price: 440 },
    { id: 'regular-1kg',  dietaryType: 'Regular', weight: '1kg',  weightGrams: 1000, price: 840 },
    { id: 'eggless-500g', dietaryType: 'Eggless', weight: '500g', weightGrams: 500, price: 390 },
  ],
  bestseller: false,      // only set true with written owner confirmation
  description: null,      // ingredient copy, only when the owner supplies it
}
```

**Photos** → drop files into `assets-src/`, run `npm run images`, then point the entry in
`src/data/imagery.js` at the new key and remove `placeholder: true`.

**Brand logo** → add the file to `public/assets/logo/` and replace `<LogoMark/>` in
`src/components/ui/Logo.jsx` with an `<img>`. The component API stays the same.

## Deployment (Vercel)

1. Push this repository to GitHub.
2. In Vercel: **Add New → Project → import the repo**. The framework is auto-detected as Vite.
3. Build command `npm run build`, output directory `dist` (already set in `vercel.json`).
4. Add an environment variable once the domain exists:

   | Key             | Value                         |
   | --------------- | ----------------------------- |
   | `VITE_SITE_URL` | `https://your-domain.com`     |

   This drives canonicals, Open Graph URLs, `sitemap.xml` and `robots.txt`.
5. Deploy. Then add the custom domain in **Settings → Domains**.
6. Submit `https://your-domain.com/sitemap.xml` in Google Search Console.

Without `VITE_SITE_URL`, the site builds against `https://cakencrush.example.com` as a
documented placeholder — nothing breaks, but canonical URLs will need a redeploy to correct.

Full details: [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

## Guardrails

`npm run audit` fails the build if the codebase ever contains:

- an `aggregateRating`, `ratingValue` or `reviewCount` (no verified reviews exist),
- a founding year, award claim or customer-count claim,
- a placeholder `href="#"` or `javascript:` link,
- a hard-coded Swiggy / Zomato / Instagram / Facebook URL,
- an image reference without a generated file or descriptive alt text.

Menu prices were entered from the brief and are **provisional pending owner approval**.
